# Install AgentOrchestra as a plugin

AgentOrchestra ships one dual-host plugin bundle at `AgentOrchestra/plugin/`:

- **Codex**: portable `plugin.json`, compatibility `.codex-plugin/plugin.json`, `skills/agentorchestra/SKILL.md`, `mcp.json` / `.mcp.json`.
- **OpenCode**: `package.json` -> `opencode-server.js`, which registers the local MCP server, the skill and two commands.

The scheduler core is bundled under `plugin/server/` so the installed plugin is self-contained. `plugin/` is generated by:

```bash
node scripts/build-plugin.js
```

Re-run it after changing `src/`, `config/`, `examples/`, `SKILL.md` or docs.

## Codex

### Repository marketplace

From the workspace root:

```bash
codex plugin marketplace add .
codex
/plugins
```

The repo marketplace file is `.agents/plugins/marketplace.json`; it points at `./AgentOrchestra/plugin`. The project enable entry is `.codex/config.toml`:

```toml
[plugins."agentorchestra@agentorchestra-local"]
enabled = true
```

Codex loads project config only for trusted projects. After installing, start a new session so bundled skills and MCP tools load.

### Personal marketplace

Copy `AgentOrchestra/plugin/` to `~/.codex/plugins/agentorchestra/`, then add an entry to `~/.agents/plugins/marketplace.json` pointing at that folder. The folder must contain the manifests and `server/`.

### Host model sync

Codex does not expose a stable subscription model-list API to plugins. Use the MCP tool:

```json
{
  "models": [
    { "providerID": "openai", "id": "model-id", "name": "Model", "contextTokens": 200000 }
  ],
  "source": "codex",
  "billing": "subscription",
  "privacy": "trusted",
  "executor": "codex"
}
```

Call `orchestra_sync_models`, then `orchestra_plan_pool`. Do not set `billing: subscription` unless the model really draws from a subscription rather than API credits.

To see automatic recommendations with evidence before choosing:

```text
/orchestra-models
```

or from a shell:

```bash
node src/cli.js models classify --json
```

The Codex plugin also ships a `SessionStart` hook that runs `server/sync-codex-host.js`, reading only auth mode and the local model cache (no token values) to refresh Codex host models on each session start.

### MCP behavior

Codex starts:

```text
node ./server/launch-mcp.js
```

with the plugin root as cwd. State defaults to `PLUGIN_DATA` (when Codex provides it) or `~/.agentorchestra`. Bundled `config/` and `examples/` are fallbacks, so the plugin works without copying config into the state directory.

### Verify without Codex

From `AgentOrchestra/plugin/`:

```bash
node server/cli-plugin.js doctor
node server/cli-plugin.js demo --reset
node server/cli-plugin.js status
```

## OpenCode

Add the plugin to the workspace `opencode.json`:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    {
      "package": "./AgentOrchestra/plugin",
      "options": {
        "root": "./AgentOrchestra",
        "hostBilling": "unknown",
        "hostPrivacy": "unknown",
        "hostExecutor": "opencode"
      }
    }
  ],
  "permissions": [
    { "action": "agentorchestra_*", "resource": "*", "effect": "allow" }
  ]
}
```

The plugin's `setup()`:

1. registers a local MCP server named `agentorchestra` using `server/launch-mcp.js`;
2. sets `AGENTORCHESTRA_ROOT` to `options.root` (or the project directory);
3. registers the `agentorchestra` skill;
4. adds `/orchestra-status`, `/orchestra-run` and `/orchestra-models` commands;
5. reads `ctx.model.list()` on setup and before each prompt, writing `host-models.json`;
6. starts a loopback execution bridge that calls the user's already-authenticated host models through OpenCode's `ctx.experimental.generate.text`, so worker execution does not require an extra API key or CLI;
7. preserves a confirmed billing/privacy boundary when later refreshes pass unknown options.

Confirm the boundary once via `/orchestra-models` (the agent calls `orchestra_confirm_host_models`) or:

```bash
node server/cli-plugin.js models confirm --billing subscription --privacy trusted --executor opencode
```

Only set `hostBilling` / `hostPrivacy` after confirming the provider's billing and data policy. Unknown values stay excluded from cost-sensitive execution; the pool reports the shortage instead of guessing.

The plugin ships a **neutral** default `config/host-policy.json` with every provider disabled until that user confirms it. Do not bake one user's choices into the plugin.

For each future user:

1. `/orchestra-models` or `orchestra_classify_host_models` produces recommendations with evidence and confidence.
2. The user confirms billing/privacy per provider through `orchestra_set_provider_policy` (or `models set-provider`).
3. The confirmed choice is written to that user's `<state-root>/.orchestra/host-policy.json`, which overrides the shipped neutral default on every model load.

This workspace has its own local choice in `.orchestra/host-policy.json`; that file is local state and is not part of the plugin bundle.

If `options.root` is omitted, state is project-scoped under the active OpenCode directory. With the example above, state is shared with the CLI under `AgentOrchestra/.orchestra`.

### Published package

`plugin/` is also an npm package (`agentorchestra-opencode-plugin`) with a dependency on `@opencode/plugin`. Publish it after running the build. For local development, the `plugins` path form above is enough.

## State separation

Codex and OpenCode can use different state roots. That is intentional:

- Codex plugin default: `PLUGIN_DATA` or `~/.agentorchestra`.
- OpenCode example: `AgentOrchestra/.orchestra` via `options.root`.
- CLI: `AgentOrchestra/.orchestra` by default.

Use the same `AGENTORCHESTRA_ROOT` / `options.root` if you want both hosts to share a project state. Do not run two schedulers against the same root simultaneously; the run lock rejects a second active run, but plan/policy edits should be serialized by the operator.

## What the plugin does not do

- It does not bundle model credentials.
- It does not make mock output real.
- It does not install SolidWorks or a CAD kernel.
- It does not bypass Codex/OpenCode permission or sandbox policy.
- It does not publish to the public plugin directory; that requires review and a remote MCP endpoint for the public catalogue.
