# AgentOrchestra

**Cost-aware, verification-driven multi-model orchestration for long engineering work.**

AgentOrchestra is not a swarm-of-chat-agents demo. It is a deterministic scheduler with:

- DAG tasks, dependencies and resumable state
- cost/quality model routing with hard privacy and budget gates
- evidence-bound acceptance, independent review and human gates
- single-writer resource locks (for SolidWorks-style shared artifacts)
- versioned artifacts, shared memory and context packets
- CLI, MCP stdio server and a local dashboard
- zero runtime dependencies, Node.js 20+

The main model keeps the decisions. Workers do bounded tasks. The scheduler owns state, money, locks and proof.

> **Honest status:** the end-to-end offline demo, the OpenCode plugin path and one **real free opencode-go host model** call are verified on this machine (45 tests including plugin bundle checks, 8/8 routing eval). Paid/subscription domestic models and Codex model calls were not exercised. Mock output is explicitly labelled simulated and is never engineering evidence. See [docs/VERIFICATION.md](docs/VERIFICATION.md).

## Install as a plugin (Codex + OpenCode)

The installable bundle is `AgentOrchestra/plugin/`, generated by `npm run build:plugin` and verified by `npm run verify:plugin`.

- **OpenCode**: `opencode.json` loads `./AgentOrchestra/plugin`. The plugin's server part auto-registers the local MCP server, the `agentorchestra` skill, `/orchestra-status` / `/orchestra-run` / `/orchestra-models`, and host-model refresh hooks.
- **Codex**: the same folder is a Codex plugin with `plugin.json`, `.codex-plugin/plugin.json`, `skills/agentorchestra/SKILL.md`, and a stdio MCP server declared by `mcp.json` / `.mcp.json`. A repository marketplace is at `.agents/plugins/marketplace.json`; run `codex plugin marketplace add .`, then `/plugins`.

See [docs/PLUGIN_INSTALL.md](docs/PLUGIN_INSTALL.md). The plugin's OpenCode server path was loaded live in OpenCode (log: `loading plugin .../opencode-server.js`, `mcp connected server=agentorchestra tools=17`), and the loopback host bridge reported `available — OpenCode host bridge reachable`. This workspace's confirmed choices live in `.orchestra/host-policy.json`: `opencode-go` common domestic + free models are enabled with `trusted` privacy; `opencode` free models are enabled for `public` tasks; `openai` stays as paid API and blocked by subscription billing mode. The **shipped plugin defaults in `config/host-policy.json` stay neutral/disabled** so future users must make their own choice after `models classify` / `/orchestra-models`. A real `opencode-go/hungerg-free` smoke task completed with score 100, real evidence, 7.1s and ¥0 API spend. Codex manifests and the bundled MCP handshake are validated; an actual Codex CLI install was not possible on this machine.

## Why this shape

The useful part is not “call a free model”. It is making the cheap choice **safe**:

1. **Adequacy first.** Capability fit is checked before price is scored. A free model that misses the bar is rejected, not accepted.
2. **Hard boundaries.** Privacy level and budget are filters, not soft preferences. Zero-extra-paid means API models are never silently used.
3. **Evidence gates.** Acceptance checks artifacts, required terms, JSON verdicts, code blocks and evidence claims. “Tests passed” without a command/output fails.
4. **Escalation.** A failed model is excluded and the next attempt must be stronger. When nothing adequate fits, the task waits for a human/budget decision.
5. **Single writer.** Shared resources are leased; two SolidWorks/assembly writers cannot overlap.
6. **Resumability.** State is persisted after every transition. Restarting resumes; accepted work is not redone.
7. **Honest reporting.** Simulated, real, main-model and human-approved evidence are distinct. Subscription quota is `unknown`.

## Architecture

```text
Codex / OpenCode / CLI / dashboard
                │
        SKILL.md + MCP tools
                │
        AgentOrchestra scheduler
   ┌────────────┼─────────────┬──────────────┐
   │            │             │              │
 Router       DAG           Quality gate   Workspace
 cost/privacy deps/retry    evidence/review locks/artifacts
   │            │             │              │
   └──────── Provider hub ────┴──────────────┘
          mock | CLI | OpenAI-compatible
                │
       .orchestra/state.json + journal.jsonl
       workspace/tasks + artifacts/<task>/attempt-N
```

- `src/router.js` — eligibility, score, escalation and reviewer selection.
- `src/scheduler.js` — DAG execution, budgets, locks, review, human gates, resume.
- `src/quality.js` — deterministic acceptance + reviewer combination.
- `src/providers/` — mock, OpenCode/Codex CLI templates, OpenAI-compatible HTTP.
- `src/store.js` — atomic JSON snapshot + append-only journal (pluggable store boundary).
- `src/workspace.js` — isolated task directories and versioned artifacts.
- `src/dashboard.js` / `src/dashboard.html` — local console.
- `src/mcp.js` — stdio JSON-RPC MCP server.

### Persistence note

The design brief proposed SQLite. This machine has no Python and native `better-sqlite3` cannot build, so V1 uses an atomic JSON snapshot plus an append-only JSONL journal. The store API is isolated; a SQLite adapter can replace it in V2 without touching the scheduler. This is a deliberate, documented trade-off, not a claim that the current store is SQLite.

## Model pool, billing and pins

The product is **one brain + a bounded worker pool**, not a catalogue of every model.

```text
pool target = policy.poolSize "auto" ? maxConcurrency : explicit size
reviewer reserve = one slot when reviewMode != off
pin precedence = task pin > role pin > all pin
```

- `billingMode: "subscription"` (default) allows free/local/subscription and rejects API-metered models. `free-first` also rejects API. `allow-api` requires an explicit budget.
- Pins fix a model, but never bypass privacy, budget or quality. An ineligible pin returns `pin_ineligible`; there is no silent fallback.
- `poolSize: "auto"` matches the subagent/concurrency limit. If there are not enough adequate models, the pool reports a shortage instead of filling slots with bad models.
- `node src/cli.js pool` and `orchestra_plan_pool` show each slot, reviewer reserve, free share, shortages and estimated API cost per wave.
- Host models from a harness are catalog entries. Unknown billing/privacy stays excluded until confirmed.

```bash
node src/cli.js pool
node src/cli.js policy --billing subscription --pool-size auto --pin reviewer=provider/model
node src/cli.js policy --unpin reviewer
```

## Routing model

```text
quality   = role-weighted capability − (difficulty − 1) × 7
threshold = 24 + difficulty × 5 + tier bonus + critical bonus
score     = q × quality + (1 − q) × costScore + history − latency
q         = qualityPreference / 100
```

Hard filters run first: availability, provider allowlist, privacy rank, billing mode, unknown cost/privacy, zero-extra-paid, API budget, context size, and the minimum quality bar. Only survivors are scored. A pin narrows the candidate set to that model; it does not skip the filters.

At `q=0` a free model that clears the bar wins. At `q=100` a high-capability model can win if the budget allows. At any `q`, a cheap model that misses the bar is excluded. The acceptance threshold is **not** derived from the slider.

## Privacy

| Task confidentiality | Required model boundary | Examples |
| --- | --- | --- |
| `0` public | `public` / `trusted` / `local` | public research |
| `1` internal | `trusted` / `local` | internal notes, non-patent design |
| `2` confidential | `local` | unpublished patent text, full drawings, key parameters |

Free/public models are rejected for levels 1–2. Unknown privacy is rejected unless explicitly allowed. Discovered models default to `privacy: public`; update `config/models.local.json` only after confirming the provider's data policy.

## OpenCode / Codex integration

Plugin-first is the supported path:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "plugins": [
    {
      "package": "./AgentOrchestra/plugin",
      "options": { "root": "./AgentOrchestra" }
    }
  ],
  "permissions": [
    { "action": "agentorchestra_*", "resource": "*", "effect": "allow" }
  ]
}
```

The OpenCode plugin registers the local MCP server, skill and commands. Codex installs the same bundle from `.agents/plugins/marketplace.json` (or a personal marketplace) and loads `mcp.json` + `skills/agentorchestra/SKILL.md`.

For development, the direct MCP entry still works as a fallback:

```jsonc
{
  "mcp": {
    "servers": {
      "agentorchestra": {
        "type": "local",
        "command": ["node", "src/mcp.js"],
        "cwd": "AgentOrchestra",
        "codemode": false
      }
    }
  }
}
```

The project skill is also at `.opencode/skills/agentorchestra/SKILL.md` as a local fallback. Codex/other agents read the root `AGENTS.md`.

CLI adapter templates live in `config/providers.json`. They are **unverified templates** until you run them against your installed versions. `doctor` reports missing commands and unverified flags.

## Limits

- No production sandbox: provider CLIs and script nodes run with the host user's authority. Use a dedicated machine/account for untrusted work.
- No real quota API: subscription remaining quota is `unknown`.
- No SolidWorks kernel/API integration in V1; only the resource lock and work contract.
- API cost estimates use configured prices and estimated tokens; they are guards, not invoices.
- Dashboard is loopback-only and has no multi-user auth.
- Real CLI flags may drift; verify with `doctor` and a small smoke task.
- The JSON store is single-process. Do not run two schedulers against the same root.
